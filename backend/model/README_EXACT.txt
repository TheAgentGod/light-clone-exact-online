LIGHT CLONE EXACT v1.1

Why this exists
---------------
The previous package contained a hidden mismatch:
the validated test images were encoded with the JPEG quantization tables
copied from the reference Phlegethon output, but apply_light_clone_v1.py
saved JPEGs with quality=95.

That means an app using the old script was NOT reproducing the validated
pipeline.

Required implementation
-----------------------
1. Use apply_light_clone_exact.py.
2. Do not re-encode the returned JPEG with Sharp, Canvas, ImageMagick,
   browser compression, CDN image optimization, or another JPEG encoder.
3. Return the generated file bytes as-is.
4. Do not add ICC profiles or metadata after generation.
5. Preserve original dimensions.
6. RGB input -> model -> exact JPEG tables -> response/download.

Self-test
---------
selftest_A.jpg and selftest_B.jpg were regenerated by the exact script.
verification.json tells whether they are byte-identical to the known-good
outputs that previously scored 97% Real and 96% Real in the user's detector.

If a deployment changes the JPEG bytes after apply_light_clone_exact.py,
the implementation is not equivalent to the validated pipeline.
